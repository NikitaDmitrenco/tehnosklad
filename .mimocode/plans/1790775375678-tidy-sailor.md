### Правила прогона (содержимое будущего файла — от Владельца):
- **Headed:** браузер открывается на машине Владельца, он видит прогон (`--headed`); никаких headless-запусков без его ведома.
- **Лог падений:** после каждого прогона упавшие тесты записывать в отдельный файл (`docs/e2e-failed-tests.md`): ID сценария (ADM-*), заголовок, что проверял, краткий текст ошибки/классификация.
- **Только тестовая БД:** исключительно локальный Supabase (`127.0.0.1`/`localhost`, `CATALOG_DATA_SOURCE=supabase`); боевой/remote проект Supabase запрещён — перед запуском сверять `NEXT_PUBLIC_SUPABASE_URL` (уже страхуется guard'ом в `e2e/helpers/env.ts`, но прогон не начинать без проверки).
- **Запуск только по команде Владельца** — агент обязан получить явное «запускай» перед любым `npx playwright test`/`npm run test:e2e*`.
- Файл также фиксирует: пре-флайт чек-лист (сервер на :3000 = local production-like, Supabase up, admin ensured, port один), форма команд (single-file → area → suite), и что агент ссылается на файл в каждом прогон-сообщении.
