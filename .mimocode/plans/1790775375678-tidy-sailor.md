# План: E2E-тесты админки Tehnosklad (batch-написание → отдельный прогон)

## Суть нового потока (по фидбеку владельца)
1. **Фаза A — написать ВСЕ оставшиеся тесты без прогона Playwright.** Никаких `npx playwright test` до полного написания.
2. **Фаза B — отдельный прогон и стабилизация** всех spec-файлов (по областям: прогон → триаж → `--repeat-each=3` → фикс-коммиты).
3. **Фаза C — финальная верификация** (двойной прогон без ресета + после ресета, typecheck/lint/prettier/unit/chromium-baseline) и документация.

Честные риски batch-подхода (приняты осознанно):
- локатор из отчёта может не совпасть с live → массовый триаж в Фазе B; смягчение: **каждый локатор сверяется со source-кодом `src/**` (read-only)**, а не только с отчётом; для уже снятых страниц (login/dashboard/categories) есть live-снапшоты;
- ошибки общих паттернов/хелперов проявятся позже → исправления пойдут batch-коммитами Фазы B;
- статические проверки (`tsc`, `prettier`) — НЕ «прогон тестов»: запускаются после каждого написанного блока, чтобы не копить мусор. Playwright-прогоны — только Фаза B.

## Фаза B — прогон и стабилизация (отдельно)
По одной области: `npx playwright test e2e/admin-<area>.spec.ts --project=admin --reporter=line` → триаж по правилу 4 (баг теста → фикс; среда/тайминг → усиление ожиданий; реальный баг приложения → `fixme`/`fail` + запись в coverage) → `--repeat-each=3` → фикс-коммит. Затем совместные прогоны всех написанных для доказательства параллельной изоляции.
