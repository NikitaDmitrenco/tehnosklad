# Запуск сервера + E2E-прогон по docs/e2e-run-rules.md

## Контекст

Владелец (в feedback) подтвердил: сервер на :3000 намеренно не запущен — его запускает агент; затем агент прогоняет тесты. Это явная команда на запуск → правило 1 (разрешение владельца) выполнено.

Дополнительное требование владельца: **«чтобы я видел как браузер открывается и что там происходит»** — прогон идёт в видимом окне терминала со стримингом вывода, браузеры только headed (окна Chromium на рабочем столе владельца), ничего не скрыто/не свёрнуто кроме лог-окна самого сервера.

**Выбранный объём прогона (решил сам, never-ask): весь admin-сьют** — `npm run test:e2e:admin -- --headed --reporter=list`. Причина: владелец не назвал область, лога прошлых прогонов (`docs/e2e-failed-tests.md`) не существует ⇒ «следующую» область по coverage определить не из чего; форма «весь admin-сьют» описана в самих правилах. Публичные e2e-проекты в правилах не упоминаются — не включаем. Флаги не добавляем (workers=3 по конфигу; если параллельные окна мешают смотреть — повторный запуск с `--workers=1` по отдельной команде).

## Шаги

1. **Node 22 в шелле запуска** (пункт 1 чек-листа):
   ```powershell
   $env:PATH = [System.Environment]::GetEnvironmentVariable("PATH", "User") + ";" + $env:PATH
   fnm env --shell powershell 2>&1 | Invoke-Expression; fnm use
   node -v   # ожидаем v22.x
   ```
2. **Сервер** (пункт 4): `npm run build` (по букве правил, несмотря на свежий `.next`) → detached `npm start`:
   ```powershell
   Start-Process -FilePath "npm" -ArgumentList "start" -WindowStyle Minimized
   ```
   (`Start-Process` наследует env с уже переключенным Node 22; окно сервера свёрнуто — владелец просил видеть прогон, а не лог next start.)
3. **Повторный пре-флайт, показать владельцу**: ровно один `LISTEN` на :3000 (`Get-NetTCPConnection -LocalPort 3000 -State Listen`) + `curl.exe -m 10 -s -o NUL -w "%{http_code}" http://127.0.0.1:3000/admin/login` → `200`.
4. **Запуск — на виду у владельца**: в сообщении явно подтвердить пункты 1–4 правил, затем открыть **видимое окно PowerShell на рабочем столе** (не minimized), в котором прогон идёт вживую:
   ```powershell
   $log  = Join-Path $env:TEMP "tehnosklad-e2e-run.log"     # вне репозитория, мимо git
   $exit = Join-Path $env:TEMP "tehnosklad-e2e-run.exit"     # маркер завершения
   Remove-Item $log,$exit -ErrorAction SilentlyContinue
   $cmd  = "npm run test:e2e:admin -- --headed --reporter=list 2>&1 | Tee-Object -FilePath '$log'; Set-Content -Path '$exit' -Value `$LASTEXITCODE"
   Start-Process powershell -ArgumentList '-NoExit','-Command',$cmd    # Normal window, stays open
   ```
   - Владелец видит: окно терминала с live-выводом `list`-репортёра + окна Chromium (`--headed`) по мере выполнения тестов (workers=3 ⇒ до 3 окон параллельно).
   - `-NoExit` — окно остаётся после финиша, владелец может прочитать итог.
   - Файлы лога/маркера — в `$env:TEMP`, чтобы не засорять репозиторий и не попасть под очистку `test-results/` со стороны Playwright.
   - Playwright-конфиг (`playwright.config.ts:18-23`) при занятом :3000 переиспользует наш prod-сервер (`reuseExistingServer: true`) — dev-сервер не поднимется.
5. **Ожидание**: поллинг existence `$env:TEMP\tehnosklad-e2e-run.exit` (цикл с паузой), затем чтение exit-кода и хвоста `$log` для отчёта.
6. **Лог после прогона** (правило 4): создать `docs/e2e-failed-tests.md` (файла нет) и добавить секцию по протоколу:
   `## <YYYY-MM-DD HH:MM> · npm run test:e2e:admin (admin, headed, repeat=1) · итог X passed / Y failed`,
   при падениях — таблица с обязательной классификацией (баг теста / среда / баг приложения / расхождение отчёт↔live); без падений → строка `Падений нет`.
7. **Отчёт владельцу**: итоги, падения с классификацией. Фиксы падений — только по отдельной команде (правила: «фиксы — отдельными коммитами»), в этот план не входят.

## Ограничения (из правил, жёсткие)

- Только `--headed`; headless — только по явному разрешению.
- Только localhost:54321 / :3000; никаких внешних URL, `PLAYWRIGHT_TEST_BASE_URL` не трогать.
- Никаких фоновых/тихих прогонов — ровно один запуск из шага 4; окно прогона видимое (не свёрнутое), это не скрытый запуск.
- Владелец должен видеть вживую: окно терминала с выводом репортёра и открытые окна Chromium.
