# Правила прогона E2E-тестов (обязательны для агента)

Этот файл — обязательный чек-лист **перед каждым запуском** любых тестов
(`npx playwright test …`, `npm run test:e2e*`). Агент обязан прочитать его и
явно подтвердить соблюдение пунктов 1–4 в сообщении о запуске.

## Жёсткие правила (от владельца)

1. **Запуск только по команде владельца.** Никакой прогон не начинается без
   явного разрешения («запускай» / «можно запускать»). Тихих, фоновых и
   «проверочных» прогонов не бывает.
2. **Headed-режим — браузер виден владельцу.** Все прогоны выполняются с
   `--headed` (окна Chromium открываются на машине владельца). Headless
   (`--headless`) — только если владелец явно разрешил.
3. **Только тестовая БД — боевая запрещена.** Перед запуском убедиться:
   - `NEXT_PUBLIC_SUPABASE_URL` в `.env.local` указывает на
     `http://127.0.0.1:54321` (локальный Supabase в Docker);
   - `CATALOG_DATA_SOURCE=supabase`, `AI_PROVIDER=fallback`;
   - remote/боевой проект Supabase не используется нигде — код тестов и
     хелперов дополнительно защищён guard'ом в `e2e/helpers/env.ts`
     (падает, если URL не localhost); guard не заменяет пре-флайт-проверку.
4. **Лог падений — в отдельный файл.** После КАЖДОГО прогона (в том числе
   успешного — тогда секция «Падений нет») дополнить
   `docs/e2e-failed-tests.md` (протокол внизу этого файла).

## Пре-флайт чек-лист (выполнить и показать результат владельцу)

| #   | Проверка                                           | Команда / признак                                                                                                                          |
| --- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Node 22 (fnm)                                      | `$env:PATH=…; fnm env --shell powershell \| Invoke-Expression; fnm use`                                                                    |
| 2   | Supabase поднят                                    | `npx supabase status` → running                                                                                                            |
| 3   | Тестовая БД в `.env.local`                         | `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321`                                                                                          |
| 4   | Ровно один сервер на :3000 (local production-like) | `Get-NetTCPConnection -LocalPort 3000 -State Listen`; `curl.exe -m 10 -s -o NUL -w "%{http_code}" http://127.0.0.1:3000/admin/login` → 200 |
| 5   | Тестовый админ существует                          | `node scripts/local-test/ensure-admin.mjs` (идемпотентно) при сомнениях / после ресета                                                     |
| 6   | Разрешение владельца на запуск получено            | явная команда в чате                                                                                                                       |

Сервер на :3000 — только локальный (`npm run build` → `npm start`).
Никаких запусков против внешних URL (`PLAYWRIGHT_TEST_BASE_URL` не менять).

## Форма команд (по возрастанию объёма)

```powershell
# одиночный файл (обычная форма Area-прогона)
npx playwright test e2e/admin-<area>.spec.ts --project=admin --headed --reporter=list

# стабилизация
npx playwright test e2e/admin-<area>.spec.ts --project=admin --headed --reporter=list --repeat-each=3

# весь admin-сьют
npm run test:e2e:admin -- --headed --reporter=list
```

Порядок областей — как в `docs/admin-e2e-test-coverage.md`.
Тесты падают → триаж по правилу классификации (баг теста / среда / баг
приложения → `test.fixme` + запись в coverage); фиксы — отдельными коммитами.

## Протокол лога падений (`docs/e2e-failed-tests.md`)

После каждого прогона файл дополняется секцией:

```markdown
## <YYYY-MM-DD HH:MM> · команда (область, flags, repeat=N) · итог X passed / Y failed

| ADM-ID | Заголовок теста | Что проверял (1 строка) | Классификация                                                        | Краткий текст ошибки   |
| ------ | --------------- | ----------------------- | -------------------------------------------------------------------- | ---------------------- |
| …      | …               | …                       | баг теста / среда / баг приложения (BUG-xx) / расхождение отчёт↔live | первая значимая строка |
```

Классификация обязательна: падение без классификации считается незакрытым.
Успешный прогон: строка `Падений нет` без таблицы.
