# Расчёт хостинга для Tehnosklad

> Оценка инфраструктуры и стоимости для текущей архитектуры: **Next.js 16 (App Router) на Vercel + Supabase (Postgres / Storage / Auth)**.
> Тарифы указаны по публичным ценам на момент расчёта — перед оплатой сверьтесь с актуальными планами Vercel и Supabase.

## 2. Что определяет нагрузку

| Фактор                 | Что в коде                                                                                                                              | Последствие                                                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Рендеринг**          | `force-dynamic` на публичном layout — `src/app/(public)/[locale]/layout.tsx:21`                                                         | HTML не кешируется на CDN → **каждый просмотр = вызов серверной функции**                     |
| **Data-cache**         | `unstable_cache` с `revalidate: 300` на всех запросах каталога — `src/features/catalog/data.ts:44-190`                                  | Должен снимать нагрузку с БД, но см. следующую строку                                         |
| **Счётчик просмотров** | `recordProductView` вызывает `revalidateTag("products")` — `src/features/catalog/data.ts:85`                                            | Под трафиком кеш сбрасывается чаще, чем раз в 5 минут → **почти все рендеры идут в Supabase** |
| **Изображения**        | Оригиналы отдаются как CSS `background-image` — `src/components/catalog/product-illustration.tsx:24`; ни `next/image`, ни трансформаций | Весь вес медиа = **egress Supabase Storage**, а не трафик Vercel                              |
| **Вес медиа**          | Товары ~50 КБ/шт (хорошо). **Категории ~366 КБ/шт × 16 ≈ 5.9 МБ** на первой загрузке каталога                                           | Главный драйвер egress                                                                        |
| **Объём данных**       | Каталог + `product_views` с ретеншном 31 день                                                                                           | БД < 100 МБ, Storage < 100 МБ — пренебрежимо мало                                             |

## 3. Сценарии трафика и расчёт потребления

Сценарии для локального магазина бытовой техники (Комрат, Молдова):

| Показатель                     | **A — запуск**<br>5k визитов / 20k просмотров | **B — рабочий режим**<br>20k / 80k | **C — пик с рекламой**<br>90k / 350k |
| ------------------------------ | --------------------------------------------: | ---------------------------------: | -----------------------------------: |
| Вызовы функций Vercel          |                                       ~30 000 |                           ~115 000 |                             ~500 000 |
| Fast Data Transfer (Vercel)    |                                         ~2 ГБ |                              ~8 ГБ |                               ~35 ГБ |
| Fluid Active CPU               |                                         < 1 ч |                               ~3 ч |                                ~11 ч |
| **Egress Supabase (картинки)** |                                    **~35 ГБ** |                        **~140 ГБ** |                          **~630 ГБ** |
| Размер БД                      |                                        ~30 МБ |                             ~50 МБ |                               ~90 МБ |
| Storage                        |                                        ~60 МБ |                             ~60 МБ |                               ~60 МБ |

### Vercel — запаса хватает с избытком

Лимиты плана Pro (≈1 ТБ трафика, 10 млн edge-запросов, ~1 млн инвокаций, ~4 CPU-часа Fluid) закрывают даже сценарий C. Переработка возможна только по Active CPU и составит **$1–3 в месяц**.

### Supabase — узкое место по egress

| Тариф | Включённый egress | Сценарий A       | Сценарий B | Сценарий C                |
| ----- | ----------------- | ---------------- | ---------- | ------------------------- |
| Free  | 5 ГБ              | ❌ превышение ×7 | ❌ ×28     | ❌ ×126                   |
| Pro   | 250 ГБ            | ✅               | ✅         | ❌ +380 ГБ → **+$34/мес** |

Размер БД и Storage не создают проблем ни на одном тарифе: 8 ГБ БД и 100 ГБ Storage в Pro против фактических ~90 МБ и ~60 МБ.

## 4. Вердикт

> ### Vercel Pro ($20/мес за место) + Supabase Pro ($25/мес) = **$45/мес**
>
> ≈ 41 € ≈ 800 MDL. Плюс домен: `.com` ~$12/год, `.md` — $25–50/год.

### Почему бесплатные тарифы не подходят

| Тариф             | Блокирующая причина                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| **Vercel Hobby**  | Условия запрещают коммерческое использование, а это магазин со сбором лидов                           |
| **Supabase Free** | Проект уходит в паузу после 7 дней неактивности, нет бэкапов, 5 ГБ egress выносится в первый же месяц |

### Конфигурация

- **Supabase compute:** включённого в Pro инстанса **Micro** (1 ГБ RAM, 2 vCPU shared) достаточно — пики в сценарии C это ~10–15 запросов/сек. Апгрейд до **Small (+$15/мес)** нужен, только если оставить проблему №1 из следующего раздела и вырасти выше сценария C.
- **Регионы:** Supabase — Frankfurt (`eu-central-1`), функции Vercel — `fra1`. Иначе каждый SSR получает +100 мс и больше на роундтрипы к БД.
- **Бэкапы:** Supabase Pro даёт ежедневные бэкапы с хранением 7 дней. Для магазина этого достаточно; PITR (+$100/мес) не нужен.

## 5. Три оптимизации, которые срежут счёт в разы

### 1. Убрать инвалидацию кеша из счётчика просмотров

`src/features/catalog/data.ts:85` — `revalidateCatalogAfterMutation("product")` внутри `recordProductView`.

Сейчас **каждый просмотр товара сбрасывает кеш всего каталога**, из-за чего пятиминутный `unstable_cache` под трафиком не работает вообще. TOP-7 популярных товаров достаточно пересчитывать по крону раз в час.

_Эффект:_ нагрузка на Supabase падает в разы, снимается риск апгрейда compute до Small.

### 2. Сжать изображения категорий

366 КБ → ~40 КБ в WebP на 600 px. Лучше генерировать превью при загрузке в админке — переменная стоимость нулевая, в отличие от Supabase Image Transformations и Vercel Image Optimization (у обоих платные квоты).

_Эффект:_ минус ~85% egress Supabase — сценарий C перестаёт выходить за 250 ГБ, экономия до $34/мес.

### 3. Снять `force-dynamic` с публичного layout

`src/app/(public)/[locale]/layout.tsx:21` → перейти на ISR с тегами; теги уже настроены в `src/features/catalog/cache.ts`.

_Эффект:_ основная масса HTML уходит на CDN, вызовы функций падают в 5–10 раз. На текущих объёмах Pro справляется и так — это страховка на рост.

> **С пунктами 1 и 2 конфигурация за $45/мес держит трафик до ~500 000 просмотров в месяц без переработок.**

## 6. Альтернатива: собственный VPS

|                                     | Vercel + Supabase | VPS (Hetzner CX22)                 |
| ----------------------------------- | ----------------- | ---------------------------------- |
| Стоимость                           | $45/мес           | ~€4.5/мес                          |
| Ресурсы                             | Managed           | 2 vCPU, 4 ГБ RAM, 40 ГБ SSD        |
| Трафик                              | Оплата по факту   | 20 ТБ включено                     |
| Миграция                            | —                 | ~неделя работы: Auth, Storage, RLS |
| Бэкапы, обновления, SSL, мониторинг | Провайдер         | **Вы**                             |

VPS потянет все три сценария. Но перенос Supabase Auth / Storage / RLS на самохост — это отдельный проект, а дальше на вас ложатся бэкапы, обновления и мониторинг. Для магазина без штатного девопса разница в $40/мес того не стоит.

**Промежуточный вариант (Vercel + самохостный Supabase на VPS) — худший из двух:** сложность самохоста остаётся, экономия всего $25/мес.
