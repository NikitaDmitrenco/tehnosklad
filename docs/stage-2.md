# Этап 2 — публичный интерфейс

## Дизайн-система

Интерфейс использует белые поверхности, почти чёрный текст и сдержанный жёлтый акцент (`--brand`). CSS-токены в `src/app/globals.css` задают цвета, радиусы, фокус, тени и состояния кнопок/полей. Контейнер ограничен `max-w-7xl`; карточки используют лёгкую границу и тень. Зелёный предназначен только для статуса наличия, красный — для скидки и ошибки поля.

## Публичные компоненты

- `components/layout` — header, mobile navigation, footer, контейнер и логотип;
- `components/catalog` — CSS-иллюстрация, карточка, сетка, галерея и интерактивный каталог;
- `components/public` — хлебные крошки, копирование телефона, диалог связи и локализованная 404.

Страницы остаются Server Components. Client Components ограничены меню, фильтрами, галереей, copy-to-clipboard и формой/диалогом связи.

## Demo data layer

`features/catalog/types.ts` описывает доменную модель, `demo-data.ts` — единственный development-only источник 3 категорий и 12 товаров, а `logic.ts` — чистые форматирование, скидки, локализацию, фильтрацию и сортировку. При подключении Supabase следует заменить источник данных репозиторием с тем же контрактом, не меняя компоненты карточек и страниц.

## Ограничения этапа

Фильтры работают локально и пока не синхронизируются с query parameters. Диалог заявки выполняет только клиентскую валидацию и честно сообщает, что данные не отправляются и не сохраняются. Изображения — локальные CSS placeholders, без внешних медиа. Перед production необходимы серверный endpoint заявки, RLS/Supabase, юридическая проверка текстов по законодательству Республики Молдова и E2E-проверки мобильной навигации, фильтров и формы.
