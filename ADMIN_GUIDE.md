# Руководство по административной панели Tehnosklad

Это руководство описывает фактическую административную панель текущей версии Tehnosklad: вход, управление каталогом, характеристики, изображения, заявки, Telegram-доставку, базу знаний и статистику AI-помощника, публичные настройки и проверку файлов.

Документ рассчитан на владельца магазина, контент-менеджера и администратора. Технические действия, которые должен выполнять только владелец Supabase-проекта или разработчик, явно отделены от ежедневной работы.

## 1. Коротко: как начать работу

1. Откройте страницу входа:
   `https://tehnosklad123.vercel.app/admin/login`.
2. Введите email и пароль пользователя Supabase Auth с активной ролью `admin`.
3. На странице **Обзор** проверьте новые заявки и ошибки Telegram.
4. Для работы с каталогом используйте рекомендуемый порядок:
   **Категории → Группы характеристик → Характеристики → Товары**.
5. Новый товар сначала сохраняйте как черновик.
6. Заполните RU/RO, характеристики и изображения, проверьте Preview RU/RO.
7. Только после проверки включайте флаг **Опубликован**.
8. После окончания работы нажмите **Выйти**.

В админке нет автосохранения. Если уйти со страницы до нажатия кнопки сохранения, несохранённые изменения будут потеряны.

## 2. Адреса и доступ

### 2.1. Основные адреса

| Назначение                     | Адрес                                          |
| ------------------------------ | ---------------------------------------------- |
| Вход в production-админку      | `https://tehnosklad123.vercel.app/admin/login` |
| Главная страница админки       | `https://tehnosklad123.vercel.app/admin`       |
| Локальная админка разработчика | `http://localhost:3000/admin/login`            |

Если production-домен изменится, путь останется тем же: `/admin/login`.

### 2.2. Какие данные используются для входа

- **Email** — email пользователя, созданного в Supabase Authentication.
- **Пароль** — пароль этого пользователя.
- Готового общего логина или пароля в репозитории нет.
- Одной записи в Supabase Authentication недостаточно. Пользователь также должен иметь:
  - активный профиль: `profiles.is_active = true`;
  - роль: `user_roles.role = 'admin'`.

Роль из `user_metadata` не используется и не даёт административный доступ.

### 2.3. Если вход не выполняется

Админка намеренно показывает одинаковое нейтральное сообщение при неправильном пароле и при отсутствии роли. Проверьте по порядку:

1. Email введён без лишних пробелов.
2. Пароль содержит не менее 8 символов.
3. Пользователь существует в нужном Supabase-проекте.
4. В `public.profiles` для его UUID установлено `is_active = true`.
5. В `public.user_roles` для того же UUID установлена роль `admin`.
6. Vercel подключён к тому же Supabase-проекту.
7. В Vercel заданы корректные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
8. После изменения переменных Vercel выполнен новый Production Deployment.

В приложении нет формы восстановления пароля и экрана управления администраторами. Восстановление доступа выполняет владелец Supabase-проекта через Authentication.

### 2.4. Выход

Нажмите **Выйти** в правом верхнем углу. Локальная сессия Supabase завершается, после чего открывается `/admin/login`.

На общем компьютере всегда выходите из админки и закрывайте окно браузера.

## 3. Навигация и общие правила интерфейса

На компьютере меню находится слева. На телефоне нажмите кнопку `☰`; закрыть меню можно крестиком, нажатием на затемнённую область или клавишей `Escape`.

Разделы:

| Раздел                    | Для чего нужен                                                          |
| ------------------------- | ----------------------------------------------------------------------- |
| **Обзор**                 | Статистика каталога, новые заявки и ошибки Telegram                     |
| **Категории**             | Разделы каталога, переводы, URL, изображения и публикация               |
| **Группы характеристик**  | Логические блоки характеристик, например «Основные параметры»           |
| **Характеристики**        | Типы параметров, варианты выбора, фильтры и привязки к категориям       |
| **Товары**                | Карточки товаров, цены, наличие, переводы, характеристики и изображения |
| **Заявки**                | Контакты покупателей, статусы, история и Telegram delivery              |
| **База знаний помощника** | Статьи RU/RO, по которым AI-помощник отвечает об условиях магазина      |
| **Статистика помощника**  | Обезличенная статистика запросов к помощнику за период                  |
| **Публичные настройки**   | Телефон, адрес, режим работы и контактный текст RU/RO                   |
| **Проверка файлов**       | Сверка Storage-файлов и записей изображений товаров                     |

### 3.1. Как сохраняются изменения

- Нажмите кнопку сохранения только один раз.
- Во время запроса кнопка блокируется и показывает «Сохранение…» или «Загрузка…».
- После успеха страница перезагрузится и появится сообщение **Изменения сохранены**.
- При ошибке появится безопасное сообщение без технических секретов.
- Если после сохранения сообщение не появилось, не вводите данные заново сразу: сначала обновите страницу и проверьте фактическое состояние записи.

### 3.2. Опасные действия

Архивирование, удаление характеристик, вариантов и изображений, а также очистка проблемных файлов требуют подтверждения браузера. Прочитайте вопрос полностью перед подтверждением.

### 3.3. Черновик, публикация и архив

- **Черновик** — запись доступна администратору, но не должна отображаться на витрине.
- **Опубликован** — запись доступна на публичном сайте при выполнении всех ограничений.
- **Архив** — запись снята с публикации, но сохранена вместе с историей и URL.

Категории и товары не удаляются безвозвратно через интерфейс. Для них используется архив.

## 4. Рекомендуемый порядок первоначального наполнения

Для нового каталога придерживайтесь следующей последовательности:

1. Заполните **Публичные настройки**.
2. Создайте категории как черновики.
3. Создайте группы характеристик.
4. Создайте характеристики.
5. Для характеристик-списков создайте варианты RU/RO.
6. Привяжите характеристики к категориям.
7. Отметьте обязательные и фильтруемые характеристики.
8. Опубликуйте готовые родительские категории, затем дочерние.
9. Создайте товар как черновик.
10. Заполните характеристики и загрузите изображения.
11. Проверьте Preview RU и Preview RO.
12. Опубликуйте товар.
13. Проверьте товар на публичных страницах `/ru` и `/ro`.

Такой порядок уменьшает количество ошибок публикации и несовместимых данных.

## 5. Раздел «Обзор»

Страница `/admin` показывает:

- общее количество товаров;
- количество опубликованных товаров;
- товары со статусом «Нет в наличии»;
- количество неархивных категорий;
- количество заявок со статусом `new`;
- Telegram-доставки в состояниях `permanent_failure` и `manual_review`;
- количество активных статей базы знаний помощника;
- пять последних заявок.

Карточки статистики являются ссылками. Например, карточка опубликованных товаров открывает список с фильтром `published`, новые заявки — список со статусом `new`, а карточка статей базы знаний — раздел **База знаний помощника**.

Рекомендуемая ежедневная проверка:

1. Откройте **Обзор**.
2. Проверьте **Новые заявки**.
3. Проверьте **Ошибки Telegram**.
4. Откройте товары «Нет в наличии» и убедитесь, что статусы актуальны.

## 6. Публичные настройки магазина

Раздел `/admin/settings` изменяет только семь заранее разрешённых публичных ключей. Секреты Telegram, Supabase и AI здесь недоступны.

| Поле                    | Что писать в RU   | Что писать в RO     | Пример                                                  |
| ----------------------- | ----------------- | ------------------- | ------------------------------------------------------- |
| Телефон для отображения | Читаемый номер    | Обычно тот же номер | `+373 69 166 172`                                       |
| Ссылка `tel:`           | Телефонная ссылка | Обычно та же ссылка | `tel:+37369166172`                                      |
| Адрес                   | Адрес по-русски   | Адрес по-румынски   | `ул. Победы, 97, Комрат` / `str. Victoriei, 97, Comrat` |
| Рабочие дни             | Дни работы        | Перевод дней работы | `Вторник–воскресенье` / `Marți–duminică`                |
| Время работы            | Время             | Обычно то же время  | `08:00–16:00`                                           |
| Выходной                | Текст о выходном  | Перевод             | `Понедельник — выходной` / `Luni — zi liberă`           |
| Контактный текст        | Призыв связаться  | Перевод             | `Позвоните нам в часы работы магазина.`                 |

Каждый ключ сохраняется отдельной кнопкой **Сохранить настройку**, но RU и RO для этого ключа обновляются одной операцией.

Правила:

- оба языка обязательны;
- значение не может быть пустым;
- максимум — 1000 символов;
- в `phone_href` используйте формат `tel:+КОДСТРАНЫНОМЕР` без пробелов;
- после изменения проверьте главную страницу, контакты, footer и телефонные кнопки на `/ru` и `/ro`.

## 7. Категории

### 7.1. Список категорий

Страница `/admin/categories` показывает:

- название RU;
- название RO или предупреждение «RO не заполнен»;
- presentation key;
- статус: **Черновик**, **Опубликована** или **Архив**;
- количество товаров.

Нажмите карточку категории для редактирования. Для создания используйте **Добавить категорию**.

### 7.2. Поля категории

| Поле                   | Назначение                        | Правила                                                             |
| ---------------------- | --------------------------------- | ------------------------------------------------------------------- |
| Родительская категория | Создаёт подкатегорию              | Нельзя выбрать саму категорию или создать цикл                      |
| Presentation key       | Выбирает визуальное представление | `fridge`, `stove`, `vacuum`; для прочих типов используйте `generic` |
| Порядок                | Определяет сортировку             | Целое число от 0; меньшее значение показывается раньше              |
| Опубликована           | Показывает категорию на сайте     | Включайте после заполнения и проверки                               |

Для каждого языка RU и RO обязательны:

| Поле перевода    |      Максимум | Примечание                                                |
| ---------------- | ------------: | --------------------------------------------------------- |
| Название         |  240 символов | Понятное пользовательское название                        |
| Slug             |  220 символов | Только латинские строчные буквы, цифры и одиночные дефисы |
| Краткое описание |  500 символов | Короткое описание раздела                                 |
| Полное описание  | 5000 символов | Основной текст категории                                  |
| SEO title        |  180 символов | Необязательно                                             |
| SEO description  |  320 символов | Необязательно                                             |

Даже черновик через текущую форму сохраняется только с заполненными RU и RO полями, кроме необязательных SEO-полей.

### 7.3. Правила slug

Допустимо:

```text
holodilniki
frigidere
vstraivaemaya-tehnika
electrocasnice-2026
```

Недопустимо:

```text
Холодильники
frigidere noi
Frigidere
frigidere_
/catalog/frigidere
```

Slug должен содержать только символы `a-z`, `0-9` и дефис между частями. Не вставляйте полный URL.

RU и RO могут иметь разные локализованные slug. В пределах одного языка slug не должен дублировать другую запись.

Если изменить slug уже опубликованной страницы, старый адрес сохраняется в истории и перенаправляет посетителя на новый постоянным redirect.

### 7.4. Иерархия и публикация

- Нельзя сделать категорию собственным родителем или потомком.
- Дочернюю категорию можно опубликовать только при опубликованном и неархивном родителе.
- Нельзя снять с публикации или архивировать родителя, пока у него есть опубликованные дочерние категории.
- Нельзя архивировать категорию с активными товарами или подкатегориями.
- Опубликованные товары требуют опубликованную неархивную категорию.

Поэтому публикуйте дерево сверху вниз, а снимайте с публикации снизу вверх.

### 7.5. Изображение категории

После первого сохранения на странице категории появляется блок загрузки.

Допустимые форматы:

- JPEG;
- PNG;
- WebP;
- AVIF;
- размер до 5 MiB.

При загрузке нового изображения metadata сначала сохраняется безопасно, после чего прежний файл удаляется. В текущем интерфейсе есть замена изображения, но нет отдельной кнопки удаления изображения без замены.

### 7.6. Архивирование категории

1. Убедитесь, что в категории нет активных товаров.
2. Убедитесь, что нет активных подкатегорий.
3. Откройте категорию.
4. В блоке **Архив** нажмите **Архивировать**.
5. Подтвердите действие.

Восстановленная категория возвращается как черновик; проверьте данные перед повторной публикацией.

## 8. Группы характеристик

Группа объединяет связанные характеристики. Примеры:

- `main_specs` — «Основные характеристики»;
- `dimensions` — «Размеры»;
- `energy` — «Энергопотребление».

Поля:

| Поле        | Правила                                                            |
| ----------- | ------------------------------------------------------------------ |
| Код         | До 80 символов; начинается с `a-z`, затем только `a-z`, `0-9`, `_` |
| Порядок     | Целое число от 0                                                   |
| Название RU | Обязательно, до 160 символов                                       |
| Название RO | Обязательно, до 160 символов                                       |
| Активна     | Определяет активность группы                                       |

Код является техническим стабильным идентификатором. Используйте понятные английские коды и не меняйте их без причины.

Удалить можно только пустую группу. Если в группе есть характеристики, сначала перенесите их в другую группу или выберите для них «Без группы».

## 9. Характеристики

### 9.1. Что такое характеристика

Характеристика описывает параметр товара, например объём, класс энергии, цвет или наличие функции. Она создаётся один раз, затем привязывается к нужным категориям.

### 9.2. Основные поля

| Поле        | Назначение и правила                                                      |
| ----------- | ------------------------------------------------------------------------- |
| Код         | До 80 символов; формат `a-z`, `0-9`, `_`, первая буква — `a-z`            |
| Группа      | Необязательно; определяет логический блок                                 |
| Тип         | Определяет формат значения товара                                         |
| Код единицы | Необязательно; например `l`, `cm`, `kg`                                   |
| Порядок     | Порядок отображения внутри структуры                                      |
| Активна     | Неактивную metadata нельзя безопасно использовать в опубликованном товаре |
| Фильтруемая | Делает характеристику доступной для фильтров, если тип это поддерживает   |

Для RU и RO указываются:

- название — обязательно, до 160 символов;
- подсказка — необязательно, до 500 символов;
- обозначение единицы — необязательно, до 40 символов.

### 9.3. Типы характеристик

| Тип в интерфейсе    | Код             | Как заполняется у товара                             | Пример                |
| ------------------- | --------------- | ---------------------------------------------------- | --------------------- |
| Текст               | `text`          | Отдельное значение RU и RO                           | Материал корпуса      |
| Число               | `number`        | Число, допускается минус и до 4 знаков после запятой | `42.5`                |
| Да/нет              | `boolean`       | Выбор Да, Нет или Не задано                          | No Frost              |
| Список              | `single_select` | Один вариант                                         | Класс энергии A+      |
| Множественный выбор | `multi_select`  | Несколько вариантов                                  | Поддерживаемые режимы |
| Цвет                | `color`         | HEX в формате `#RRGGBB`                              | `#FFFFFF`             |

Тип `range` текущей моделью не поддерживается.

Текстовую характеристику нельзя использовать как канонический фильтр. Для стандартного набора значений используйте тип «Список» или «Множественный выбор».

После появления товарных значений или вариантов тип менять нельзя. Поэтому выбирайте тип до массового наполнения каталога.

### 9.4. Варианты списка

Блок **Варианты** появляется только для `single_select` и `multi_select`.

Для каждого варианта задаются:

- код в формате `a-z`, `0-9`, `_`;
- порядок;
- Label RU;
- Label RO;
- флаг **Активен**.

Пример для `energy_class`:

| Код             | RU  | RO  |
| --------------- | --- | --- |
| `a`             | A   | A   |
| `a_plus`        | A+  | A+  |
| `a_double_plus` | A++ | A++ |

Не удаляйте вариант, который уже выбран у товара. Сначала замените или очистите это значение во всех товарах. Если вариант временно не нужен, безопаснее отключить флаг **Активен** после проверки опубликованных товаров.

### 9.5. Привязка характеристики к категориям

После сохранения характеристики откройте блок **Категории**:

1. Выберите категорию.
2. Укажите порядок.
3. При необходимости включите **Обязательная**.
4. При необходимости включите **Фильтр**.
5. Нажмите **Привязать**.

Для каждой уже привязанной категории настройки изменяются отдельно.

- **Обязательная** — товар этой категории нельзя опубликовать без значения.
- **Фильтр** — значение участвует в фильтрах каталога.
- **Порядок** — определяет позицию характеристики.

Нельзя отвязать характеристику, пока у товаров этой категории существуют соответствующие значения. Сначала очистите значения у товаров.

### 9.6. Удаление характеристики

Удалить характеристику можно только если:

- она не привязана к категориям;
- у товаров нет её значений;
- её варианты не используются.

Если нужно временно скрыть характеристику, используйте флаг **Активна** только после проверки, что она не требуется опубликованным товарам.

## 10. Товары

### 10.1. Список и поиск

Страница `/admin/products` позволяет искать по:

- названию RU/RO;
- бренду;
- модели;
- SKU.

Фильтры:

- категория;
- статус публикации: опубликованные, черновики, архив.

Карточка показывает статус, наличие, бренд, модель, SKU и цену. Текущий экран загружает до 250 последних обновлённых товаров; при существенно большем каталоге потребуется серверная пагинация.

### 10.2. Правильный порядок создания товара

1. Нажмите **Добавить товар**.
2. Выберите категорию.
3. Заполните основные данные и оба перевода.
4. Оставьте флаг **Опубликован** выключенным.
5. Нажмите **Сохранить товар**.
6. После первого сохранения заполните характеристики.
7. Загрузите изображения и alt-тексты.
8. Проверьте Preview RU и Preview RO.
9. Включите **Опубликован** и сохраните.
10. Откройте ссылки **Витрина RU** и **Витрина RO**.

### 10.3. Основные поля товара

| Поле             | Правила и рекомендации                                                         |
| ---------------- | ------------------------------------------------------------------------------ |
| Категория        | Только неархивная категория; для публикации категория должна быть опубликована |
| Бренд            | Обязательно, до 120 символов                                                   |
| Модель           | Обязательно, до 160 символов                                                   |
| SKU              | Обязательно, уникально, до 80 символов                                         |
| Цена, MDL        | Обязательно; целое число или до 2 знаков после `.`/`,`                         |
| Старая цена, MDL | Необязательно; должна быть строго больше текущей цены                          |
| Наличие          | В наличии, Нет в наличии или Под заказ                                         |
| Количество       | Необязательное целое число от 0                                                |
| Порядок          | Целое число от 0; меньшее значение имеет приоритет                             |
| Популярный       | Используется для приоритетной подборки                                         |
| Новинка          | Отмечает новый товар                                                           |
| Опубликован      | Делает товар публичным после проверки ограничений                              |

Валюта каталога фиксирована как MDL. Не вводите разделители тысяч. Примеры корректной цены: `5990`, `5990.50`, `5990,50`.

Статус наличия и количество являются отдельными полями. Поддерживайте их согласованными:

- при количестве `0` обычно выбирайте «Нет в наличии» или «Под заказ»;
- при «В наличии» указывайте реальное количество, если оно известно;
- не используйте количество как замену статусу наличия.

### 10.4. Переводы товара

Для RU и RO обязательны:

| Поле             |                    Максимум |
| ---------------- | --------------------------: |
| Название         |                240 символов |
| Slug             |                220 символов |
| Краткое описание |                500 символов |
| Полное описание  |             10 000 символов |
| SEO title        | 180 символов, необязательно |
| SEO description  | 320 символов, необязательно |

Правила slug такие же, как у категорий: только строчные латинские буквы, цифры и дефисы.

Не копируйте русский текст в RO как постоянное решение. Если перевод ещё не готов, оставляйте товар черновиком.

### 10.5. Характеристики товара

Блок **Характеристики** строится из привязок выбранной категории.

- Текст заполняется отдельно для RU и RO. Если заполнен один язык, второй тоже обязателен.
- Число принимает до 14 цифр в целой части и до 4 после запятой; допускается отрицательное значение, если это имеет смысл для параметра.
- Да/нет допускает «Не задано».
- Список позволяет выбрать один активный вариант.
- Множественный выбор позволяет отметить несколько активных вариантов.
- Цвет вводится как `#RRGGBB`.
- Пустое необязательное значение после сохранения удаляется.

Если характеристика отмечена обязательной для категории, товар можно сохранить черновиком без неё, но публикация будет отклонена.

При смене категории сохранённые характеристики должны быть совместимы с новой категорией. Если появляется ошибка, сначала очистите несовместимые значения, затем меняйте категорию.

### 10.6. Чек-лист публикации

На странице товара отображается встроенный чек-лист:

- категория опубликована и не архивирована;
- переводы RU и RO заполнены;
- обязательные характеристики заполнены;
- у всех существующих изображений заполнены alt RU и alt RO.

Дополнительно база проверяет активность характеристик и вариантов. Если хотя бы одно условие нарушено, публикация отклоняется, а прежнее корректное состояние сохраняется.

Наличие изображения не является технически обязательным условием публикации, но для реального товара рекомендуется минимум одно качественное главное изображение.

### 10.7. Preview и публичная витрина

- **Preview RU** и **Preview RO** доступны только авторизованному администратору, в том числе для черновика.
- Preview показывает контент и характеристики, но не является пиксельно точной копией публичной карточки.
- Ссылки **Витрина RU/RO** появляются только у опубликованного товара с обоими переводами.
- После публикации обязательно проверьте обе публичные ссылки в новой вкладке.

### 10.8. Архивирование товара

Архивирование:

- снимает товар с публикации;
- сохраняет данные и историю URL;
- не удаляет заявку, которая раньше была связана с товаром;
- позволяет позже восстановить товар как черновик.

Для временного отсутствия используйте статус «Нет в наличии», а не архив. Архив предназначен для товара, который больше не должен находиться в активном каталоге.

## 11. Изображения товаров

### 11.1. Требования к файлам

- JPEG, PNG, WebP или AVIF;
- размер до 5 MiB;
- фактическое содержимое файла должно соответствовать заявленному формату;
- имя и путь генерирует сервер;
- перезапись существующего файла отключена.

Не загружайте в публичный bucket документы, персональные данные, прайс-листы с закрытой информацией или другие секретные материалы.

### 11.2. Загрузка

1. Откройте сохранённый товар.
2. В блоке **Изображения** выберите файл.
3. Заполните **Alt RU** и **Alt RO** — до 240 символов каждый.
4. Укажите порядок.
5. При необходимости отметьте **Главное**.
6. Нажмите **Загрузить изображение** и дождитесь завершения.

Для первого изображения флаг **Главное** включён по умолчанию.

Хороший alt-текст кратко описывает товар на соответствующем языке, например:

- RU: `Холодильник Nord Cool 300, вид спереди`;
- RO: `Frigider Nord Cool 300, vedere frontală`.

Не используйте alt как место для ключевых слов или длинного рекламного текста.

### 11.3. Порядок и главное изображение

- Меньшее значение порядка показывается раньше.
- У товара должно быть одно осмысленное главное изображение.
- Чтобы заменить главное изображение, отметьте новый файл как **Главное** и сохраните его настройки.
- После изменения откройте публичную карточку и проверьте галерею.

### 11.4. Удаление

Удаление выполняется безопасной последовательностью: отметка metadata → удаление Storage-объекта → завершение metadata.

Если операция оборвалась, изображение может получить статус **Ожидает очистки**. В этом случае перейдите в **Проверка файлов** и завершите сверку. Не пытайтесь повторно загружать тот же файл вручную в Supabase Storage.

## 12. Заявки покупателей

### 12.1. Список заявок

Страница `/admin/leads` позволяет фильтровать заявки по:

- имени или телефону;
- статусу;
- источнику;
- языку RU/RO;
- товару;
- диапазону дат.

Текущий экран показывает до 100 последних заявок, соответствующих серверным фильтрам. CSV-экспорт — до 5000.

### 12.2. Источники заявок

| Код                     | Значение                         |
| ----------------------- | -------------------------------- |
| `home_contact`          | Контактная форма на главной      |
| `contacts_page`         | Страница контактов               |
| `home_product_card`     | Карточка товара на главной       |
| `catalog_product_card`  | Карточка товара в общем каталоге |
| `category_product_card` | Карточка товара в категории      |
| `product_page`          | Страница товара                  |
| `similar_product_card`  | Карточка похожего товара         |

### 12.3. Карточка заявки

Карточка содержит:

- имя;
- телефон со ссылкой `tel:`;
- Telegram username, если указан;
- комментарий;
- источник, путь и язык;
- время согласия;
- snapshot товара на момент заявки;
- текущую ссылку на товар, если товар ещё существует;
- историю статусов;
- состояние и попытки Telegram delivery.

Snapshot сохраняет название, цену и ссылку такими, какими они были при создании заявки. Изменение текущего товара не должно переписывать историю заявки.

Контактные данные, источник, согласие и snapshot не редактируются из админки. Администратор изменяет только статус и при необходимости вручную повторяет Telegram-доставку.

### 12.4. Статусы заявок

| Код           | Рекомендуемое значение        |
| ------------- | ----------------------------- |
| `new`         | Новая, ещё не обработана      |
| `in_progress` | Взята сотрудником в работу    |
| `contacted`   | С клиентом связались          |
| `closed`      | Работа по заявке завершена    |
| `spam`        | Спам или нерелевантная заявка |

Рекомендуемый процесс:

```text
new → in_progress → contacted → closed
```

После каждого изменения система добавляет запись в историю с предыдущим статусом, новым статусом, временем и UUID администратора.

Не помечайте заявку как `closed`, пока результат общения не зафиксирован в вашем рабочем процессе. Не удаляйте реальные заявки вручную из Supabase.

### 12.5. Экспорт CSV

Кнопка **Экспорт CSV** использует текущие фильтры списка.

Файл содержит персональные данные. Поэтому:

- экспортируйте только при рабочей необходимости;
- не отправляйте файл в публичные чаты;
- не храните его бессрочно на личном компьютере;
- после использования удалите локальную копию согласно политике хранения;
- не редактируйте заявку импортом обратно — импорт в админке отсутствует.

Значения CSV безопасно экранируются от формул электронных таблиц, но это не отменяет правил защиты персональных данных.

## 13. Telegram delivery

Заявка сначала сохраняется в базе, и только затем отправляется в Telegram. Поэтому сбой Telegram не означает потерю заявки.

| Состояние           | Что означает                           | Действие администратора                    |
| ------------------- | -------------------------------------- | ------------------------------------------ |
| `queued`            | Ожидает отправки                       | Подождать, проверить позже                 |
| `processing`        | Отправка выполняется                   | Не запускать повторно                      |
| `retry_wait`        | Telegram явно попросил повторить позже | Подождать автоматический разрешённый retry |
| `succeeded`         | Сообщение доставлено                   | Ничего не делать                           |
| `permanent_failure` | Конфигурация или постоянная ошибка     | Исправить причину, затем повторить вручную |
| `manual_review`     | Исход предыдущей попытки неясен        | Сначала проверить Telegram-чат вручную     |

Карточка показывает число попыток, message ID, HTTP status и безопасные коды ошибок.

### 13.1. Повторная отправка

Кнопка повторной отправки отображается только для допустимых неуспешных состояний.

Для `manual_review` необходимо подтвердить риск дубликата. Причина: предыдущий запрос мог быть принят Telegram, даже если приложение не получило уверенный ответ.

Порядок:

1. Откройте реальный Telegram-чат магазина.
2. Найдите сообщение по времени, имени, телефону или UUID заявки.
3. Если сообщения точно нет, вернитесь в админку.
4. Для `manual_review` установите флажок подтверждения риска.
5. Нажмите **Повторно отправить в Telegram** один раз.
6. Обновите карточку и проверьте новую попытку.

Не повторяйте доставку в состоянии `processing` и не отправляйте повторно `succeeded`.

## 14. Проверка файлов

Раздел `/admin/media/orphans` сравнивает Storage bucket `product-images` с metadata изображений.

### 14.1. Возможные состояния

| Состояние                                   | Значение                                    | Действие кнопки                                                         |
| ------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------- |
| Файл без metadata (`orphan_object`)         | Файл есть в Storage, записи изображения нет | Удаляет лишний файл                                                     |
| Metadata без файла (`missing_object`)       | Запись есть, физического файла нет          | Удаляет сломанную metadata                                              |
| Незавершённое удаление (`pending_metadata`) | Удаление прервалось между этапами           | Проверяет файл и либо восстанавливает metadata, либо завершает удаление |

### 14.2. Как пользоваться

1. Откройте **Проверка файлов**.
2. Если показано «Orphan-файлов нет», действий не требуется.
3. Для проблемной строки откройте связанный товар в новой вкладке и проверьте его изображения.
4. Вернитесь к записи и внимательно прочитайте состояние.
5. Нажмите **Очистить** или **Восстановить / завершить**.
6. Подтвердите действие.
7. Дождитесь повторной сверки.
8. Снова откройте товар и публичную карточку.

Не удаляйте такие файлы непосредственно в Supabase Storage, если проблема уже отображается в админке: интерфейс повторно проверяет актуальное состояние и поддерживает согласованность metadata.

Текущий scan ограничен 1000 папками товаров и 1000 объектами в одной папке. Для большего объёма нужен отдельный проверенный maintenance-инструмент с пагинацией.

## 15. База знаний помощника

Раздел `/admin/assistant-knowledge` хранит статьи, по которым AI-помощник на публичном сайте отвечает об условиях магазина: доставка, оплата, гарантия, возврат, самовывоз.

Помощник отвечает только по подтверждённым данным: каталог, публичные настройки, юридические документы и эти статьи. Он не придумывает условия магазина. Если условия нет в базе знаний, помощник предложит связаться с магазином по телефону из публичных настроек.

### 15.1. Список статей

Статьи сгруппированы по языку и отсортированы по дате изменения. У каждой карточки два признака:

| Признак                  | Значение                                       |
| ------------------------ | ---------------------------------------------- |
| **Активна**              | Статья участвует в ответах помощника           |
| **Выключена**            | Статья сохранена, но помощник её не использует |
| **Русский** / **Română** | Язык, на котором статья попадёт в ответ        |

### 15.2. Поля статьи

| Поле         | Что писать                                                                     |
| ------------ | ------------------------------------------------------------------------------ |
| Язык         | `Русский` или `Română` — статья используется только для вопросов на этом языке |
| Заголовок    | Короткая тема: «Доставка», «Оплата», «Гарантия»; до 160 символов               |
| Текст ответа | Сам ответ: условия, сроки, стоимость, ограничения; до 5000 символов            |
| Активна      | Флаг участия статьи в ответах                                                  |

Правила:

- заголовок и текст ответа не могут быть пустыми;
- по заголовку помощник находит статью, поэтому пишите в нём слово, которое употребит покупатель;
- каждый язык хранится отдельной статьей: RU и RO нужно создавать двумя записями;
- пишите фактами и числами («доставка по Комрату — бесплатно, по стране — 1–3 рабочих дня»), без маркетинговых обещаний;
- не указывайте в статьях персональные данные сотрудников и клиентов, реквизиты карт и внутренние инструкции: тексты статей попадают в ответ покупателю;
- для временных условий (акция, изменённый график) удобнее выключать статью флагом **Активна**, чем удалять её.

### 15.3. Порядок работы

1. Откройте **База знаний помощника**.
2. Нажмите **Добавить статью**.
3. Выберите язык, заполните заголовок и текст.
4. Сохраните статью.
5. Повторите для второго языка.
6. Проверьте ответ помощника на публичном сайте `/ru` и `/ro`, задав вопрос по теме статьи.

Удаление статьи выполняется из её карточки и требует подтверждения браузера. Удалённую статью восстановить нельзя — если статья может пригодиться позже, снимите флаг **Активна**.

## 16. Статистика помощника

Раздел `/admin/assistant-logs` показывает, как часто покупатели пишут помощнику и чем он отвечает.

В этой статистике нет текстов вопросов, IP-адресов и любых данных о покупателе: сохраняются только служебный номер запроса, язык, результат, провайдер, диапазон длительности и число показанных товаров.

### 16.1. Период

Кнопки **7 дней**, **30 дней** и **90 дней** переключают период. Выбранный период остаётся в адресе страницы, например `/admin/assistant-logs?days=30`, — такую ссылку можно сохранить в закладки.

### 16.2. Что показывают карточки

| Карточка                   | Значение                                              |
| -------------------------- | ----------------------------------------------------- |
| Всего запросов             | Сколько вопросов задали помощнику за период           |
| Ответы без AI-провайдера   | Доля и число ответов, собранных без внешнего AI       |
| Товаров в ответе в среднем | Сколько карточек товаров помощник в среднем показывал |

Ниже — четыре разбивки: результат ответа, провайдер, скорость ответа и язык вопроса, а затем таблица последних запросов.

### 16.3. Как читать показатели

- Высокая доля ответов **без AI-провайдера** — это нормально, если внешний AI не подключён: помощник отвечает по каталогу, настройкам и базе знаний. Если внешний AI подключён, а доля выросла, проверьте у разработчика ключ и доступность провайдера.
- Результат **Провайдер недоступен** или **Провайдер вернул лимит** в большом числе записей означает проблему на стороне внешнего AI.
- Среднее число товаров близкое к нулю означает, что помощник почти не находит товары по вопросам покупателей: проверьте публикацию товаров и названия категорий.
- Много ответов **Дольше 1 с** — повод сообщить разработчику.
- Пустая страница означает, что за период вопросов не было либо телеметрия не пишется. Телеметрия требует service-role ключа и не ведётся в demo-режиме и на локальной машине разработчика.

## 17. Частые ошибки и решения

### «Проверьте обязательные поля и формат значений»

Проверьте:

- пустые обязательные поля;
- slug и коды;
- формат цены;
- отрицательные значения порядка или количества;
- alt-тексты;
- RU/RO.

### «Такой slug, код или SKU уже используется»

Найдите существующую запись и выберите уникальное значение. Не добавляйте случайный пробел: он будет удалён или создаст путаницу. Для SKU используйте стабильную схему магазина.

### «Для публикации товара нужны полные переводы RU и RO»

Заполните оба языковых блока полностью и сохраните товар как черновик, затем повторите публикацию.

### «Сначала опубликуйте выбранную категорию»

Откройте категорию, проверьте RU/RO и родителя, опубликуйте её, затем вернитесь к товару.

### «Заполните все обязательные характеристики»

Откройте блок характеристик товара и заполните каждую характеристику со звёздочкой. Для текстовой характеристики нужны оба языка.

### «У каждого изображения должны быть alt-тексты RU и RO»

Проверьте каждое изображение, включая старые. Заполните оба alt и сохраните настройки изображения.

### «Тип используемой характеристики менять нельзя»

Создайте новую характеристику правильного типа, привяжите её, перенесите значения, затем удалите старые зависимости.

### «Категория используется товарами или подкатегориями»

Сначала архивируйте или перенесите товары и обработайте дочерние категории.

### «Группа содержит характеристики»

Перенесите характеристики из группы или задайте им «Без группы», затем повторите удаление.

### «Вариант уже используется в товарах»

Замените или очистите вариант во всех товарах. Если удаление не обязательно, отключите его после проверки публикации.

### «Не удалось загрузить раздел»

1. Нажмите **Повторить**.
2. Проверьте интернет.
3. Откройте другую страницу админки.
4. Проверьте статус Supabase и Vercel.
5. Если ошибка сохраняется, сообщите разработчику путь страницы, время и действие перед ошибкой.

Не отправляйте разработчику пароль, cookies, service-role key, токены Telegram или ключ AI.

## 18. Практические сценарии

### 18.1. Добавить новый товар

1. Подготовьте RU/RO названия, описания и SEO.
2. Подготовьте уникальный SKU.
3. Проверьте опубликованную категорию.
4. Создайте товар без публикации.
5. Заполните характеристики.
6. Загрузите изображения с RU/RO alt.
7. Проверьте Preview RU/RO.
8. Проверьте цену, старую цену, наличие и количество.
9. Опубликуйте.
10. Проверьте витрину RU/RO и мобильный экран.

### 18.2. Изменить цену

1. Найдите товар по SKU или названию.
2. Измените текущую цену.
3. Если указана старая цена, убедитесь, что она строго больше новой.
4. Сохраните товар.
5. Откройте обе публичные страницы и проверьте формат MDL и скидку.

### 18.3. Товар закончился

1. Откройте товар.
2. Выберите **Нет в наличии**.
3. Установите количество `0`, если учёт количества используется.
4. Не архивируйте товар, если он может вернуться в продажу.
5. Сохраните и проверьте витрину.

### 18.4. Товар больше не продаётся

1. Проверьте связанные открытые заявки.
2. Откройте товар.
3. В блоке **Архив** нажмите **Архивировать**.
4. Подтвердите действие.
5. Проверьте, что товар исчез из активного каталога.

### 18.5. Обработать новую заявку

1. Откройте карточку из **Обзор** или **Заявки**.
2. Проверьте телефон, комментарий, товар и Telegram delivery.
3. Установите `in_progress`.
4. Свяжитесь с клиентом.
5. Установите `contacted`.
6. После завершения установите `closed`.
7. Для спама используйте `spam`.

### 18.6. Заменить изображение категории

1. Подготовьте оптимизированный файл до 5 MiB.
2. Откройте категорию.
3. Загрузите новый файл.
4. Дождитесь сообщения об успехе.
5. Проверьте витрину RU/RO.
6. При ошибке очистки проверьте server logs или обратитесь к разработчику; product orphan-экран не управляет bucket изображений категорий.

## 20. Безопасность администратора

- Используйте отдельную учётную запись для каждого администратора.
- Не передавайте общий пароль через мессенджеры.
- Используйте уникальный длинный пароль и менеджер паролей.
- Не сохраняйте пароль в репозитории, README, SQL-файлах или `.env`.
- Никогда не вставляйте `SUPABASE_SERVICE_ROLE_KEY`, Telegram token или AI key в админку.
- Не добавляйте секреты в `NEXT_PUBLIC_*`.
- Не загружайте персональные или закрытые документы в публичные image buckets.
- Не оставляйте CSV с заявками на общедоступном диске.
- При увольнении или прекращении полномочий деактивируйте профиль немедленно.
- Не выполняйте ручное удаление строк и файлов в Supabase, пока существует поддерживаемая операция в админке.

Административные страницы проверяют активную роль на сервере при каждом запросе. Отключённый пользователь теряет доступ при следующей серверной проверке.

## 21. Создание и отключение администратора — только для владельца Supabase

Этот раздел не является ежедневной операцией контент-менеджера.

### 21.1. Создание

1. Откройте Supabase Dashboard.
2. Перейдите **Authentication → Users → Add user**.
3. Создайте email и пароль.
4. Скопируйте UUID пользователя.
5. В SQL Editor доверенной ролью выполните, заменив `USER_UUID`:

```sql
begin;

insert into public.profiles (id, display_name, is_active)
values ('USER_UUID', 'Administrator', true)
on conflict (id) do update
set display_name = excluded.display_name,
    is_active = true;

insert into public.user_roles (user_id, role)
values ('USER_UUID', 'admin')
on conflict (user_id) do update
set role = excluded.role;

commit;
```

6. Проверьте вход через `/admin/login`.
7. Не сохраняйте пароль или UUID в документации проекта без необходимости.

Публичную регистрацию рекомендуется держать отключённой. Обычный browser client не может назначить себе роль администратора.

### 21.2. Временное отключение

Для обратимого отключения:

```sql
update public.profiles
set is_active = false
where id = 'USER_UUID';
```

После отключения проверьте, что пользователь больше не открывает `/admin`.

### 21.3. Возврат доступа

```sql
update public.profiles
set is_active = true
where id = 'USER_UUID';
```

Перед возвратом доступа подтвердите, что роль в `user_roles` всё ещё равна `admin`.

## 22. Ограничения текущей админки

- Интерфейс администратора русскоязычный.
- Управляемый публичный контент требует RU и RO.
- Автосохранения нет.
- В приложении нет управления пользователями и сброса пароля.
- Нет массового редактирования товаров или заявок.
- Нет импорта товаров из CSV.
- Категории и товары архивируются, а не удаляются полностью.
- Изображение категории можно заменить, но отдельной кнопки удаления нет.
- Список товаров ограничен 250 последними записями.
- Список заявок ограничен 100 последними записями; CSV — 5000.
- Проверка product Storage сканирует до 1000 папок и до 1000 файлов в папке.
- Статьи базы знаний создаются отдельно для RU и RO; общей формы «сразу на двух языках» нет.
- Статистика помощника строится по 5000 последним записям периода; если записей больше, страница сообщает об этом под карточками.
- Телеметрия помощника не ведётся без service-role ключа, поэтому в demo-режиме раздел статистики пуст.
- Preview товара не является точной копией дизайна публичной страницы.
- Наличие изображения не является технически обязательным условием публикации.
- Фоновое расписание privacy retention настраивается отдельно в Supabase Cron, не в админке.

## 24. Что сообщить разработчику при проблеме

Перед обращением запишите:

1. Адрес страницы, например `/admin/products/<id>`.
2. Дату и точное время ошибки с часовым поясом.
3. Какую кнопку нажали.
4. Какие несекретные значения вводили.
5. Текст безопасного сообщения на странице.
6. Повторяется ли ошибка после обновления страницы.
7. Затронут ли публичный сайт RU/RO.
8. ID товара, категории или заявки, если он виден в URL.

Никогда не отправляйте:

- пароль;
- cookies;
- содержимое `.env`;
- service-role key;
- Telegram bot token;
- AI provider key;
- полный CSV заявок без защищённого согласованного канала.
